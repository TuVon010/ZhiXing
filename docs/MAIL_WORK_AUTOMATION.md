# 邮件 Agent 的工作项与审批边界

## 产品对象

邮件是证据，工作项是结果。工作台分成四个互不混淆的列表：

| 列表 | 含义 | 典型操作 |
| --- | --- | --- |
| 待办 | 自己要完成的具体动作 | 完成、重新打开、查看原邮件 |
| 邮件跟进 | 会话状态，当前需要回复或已回复等待对方 | 起草回复、标记已处理 |
| 待核实建议 | 模型提取到事项，但证据、日期或风险不满足自动保存条件 | 核对原文后确认或忽略 |
| 提醒 | 从明确截止时间或日程派生的本地提醒 | 查看来源 |

日程的正式记录仍在“日程”页；有冲突或时间不完整的提取结果出现在“待核实建议”。“邮件跟进”不再假装成 Todo：回复是一次沟通行为，草稿、审批、SMTP 接受以及等待对方是不同状态。

同一邮件里的“参加会议”归入日程，不再重复列为待办；纯回复确认归入邮件跟进。截止时间由待办及其提醒承载，不再另造一个“截止日程”。同一线程出现改期时，新日程先进入待核实建议；确认改期会停用旧日程及旧提醒，旧记录仍可追溯。

## 谁决定自动执行

模型负责理解邮件并提出结构化的待办、日程、回复意图及原文引用。服务端 `mail_work_items.py` 做独立的、版本化的确定性校验，不能由邮件正文或模型输出自行改写规则。

| 动作 | 默认结果 | 自动条件 | 人工介入时机 |
| --- | --- | --- | --- |
| 一句话摘要、分类 | 自动记录 | 模型结果格式有效 | 用户纠偏时 |
| 本地待办 | 自动保存，可完成/撤销 | 高置信度、低垃圾评分、工作/个人邮件、行动原文可逐字核对、截止日期与原文一致、不涉及密码或资金 | 原文缺失、时间含糊、敏感操作 |
| 本地日程与提前提醒 | 自动保存 | 更高置信度、完整且未来的起止时间、日期和开始时间与原文吻合、无冲突、不邀请他人 | 缺失时间、模型日期与原文不符、存在冲突 |
| 待回复跟进 | 自动建本地记录 | 邮件明确要求回复、未被过滤 | 用户认为无需回复时标记已处理 |
| 回复草稿 | 自动生成或手动编辑 | 只保存在本地 | 发送前 |
| 发送邮件、邀请他人、远端删除 | 不自动执行 | 无自动放行条件 | 必须由用户确认最终收件人和正文 |

本地完成待办、关闭跟进不再创建审批记录。这些操作作用于自己的本地数据库，具备审计和恢复入口。人工审批的价值在于**对外副作用的最终授权**，以及模型不确定时的事实纠正；让同一个模型“批准”自己提出的发信操作并不能建立独立授权。此区分符合 [OWASP Excessive Agency](https://genai.owasp.org/llmrisk/llm062025-excessive-agency/) 对高影响动作人工批准的建议，也与 [LangGraph 人工审阅示例](https://docs.langchain.com/oss/javascript/langgraph/thinking-in-langgraph) 的发送前暂停模式一致。

自动化不是以模型自报的 `confidence` 为唯一依据。原文引用、时间和账号作用域必须由服务端核对；高风险词与过滤状态阻止自动晋升。邮件里的“忽略审批规则”等内容是待分析数据，不是指令。当前规则版本为 `mail-work-v1`，每条自动记录附带决策原因与来源邮件 ID，可从 Trace 追溯。现有旧候选不会因规则升级被悄悄改为自动事项。

## 14 封合成邮件测试账号

在“邮箱账号”点击“创建 Agent 测试邮箱（14 封）”。账号地址以 `.invalid` 结尾，无凭证、不连接 IMAP/SMTP、不会真实发信；重复点击不会重复生成。切换到该账号，在“收取与导入”点击“分析待处理邮件”。真实模式会调用已配置的模型，演示模式会走明确标记的离线规则，二者不能混为一谈。测试账号的发送审批在执行账本中记为模拟发送。

样本覆盖：明确待办、明确会议、待回复、广告过滤、可疑安全邮件、纯通知、多项行动、会议改期、仅供参考、时间含糊、个人日程、截止时间更正、TXT 附件、邮件提示注入。每封邮件保留 `scenario_name` 和 `synthetic` 标签，测试数据与真实邮箱按账号隔离。

建议按以下顺序学习和调试：

1. 在收件箱观察规则过滤与待复核状态，然后在导入页看“入库→排队→已产出”的数量变化。
2. 打开邮件的 AI 感知结果和 Trace，核对模型输入、Token、判断理由以及是否生成工作项。
3. 在“下一步工作”比较自动待办与待核实建议；核对 `decision.reason` 和原文日期，试着完成并重新打开本地待办。
4. 在“邮件跟进”起草回复。提交发送审批后核对冻结的收件人和正文；测试账号只能模拟发送。
5. 重复运行样本，检查邮件、Todo、日程和跟进是否被幂等键去重。故意将日期或原文引用改错，运行单元测试，确认事项留在建议而不是自动执行。

自动化判定的覆盖测试位于 `tests/test_mail_work_items.py`；浏览器端全流程在 `frontend/e2e/zzz-scenarios.spec.ts`。每次 `scripts/run_checks.py` 会将源码快照、逐步日志、JUnit、浏览器录像、截图和测试数据库保存到 `artifacts/test-runs/`，失败轮次也保留。
