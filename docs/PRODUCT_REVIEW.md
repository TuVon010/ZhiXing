# 知行邮件 Agent 产品与业务评估

更新日期：2026-09-23。定位：可运行的个人邮件 Agent MVP，适合个人试用及后端/测试开发学习；不是已经完成真实邮箱和主模型生产验收的产品。

## 当前闭环

多邮箱受控收取 → 本地过滤/线程/索引 → 显式账号范围检索 → 有界 Agent 决策 → 待办、日程、提醒或草稿 → 风险审批 → 账本执行 → 通知与统一 Trace。

本轮补齐了原先影响体验的断点：审批页、草稿、待办来源和通知可打开同一个 Trace；Agent turn 与关联动作 run 分开显示状态；Web 通知中心可查看提醒并标记已读；日程创建/修改经审批后可见；邮件与动作队列轮转，历史导入自动续批。

## 实际价值与验证边界

价值主要来自跨线程查证、减少遗漏承诺、准备可审核的回复。对邮件量较少的用户，本地模型与邮箱配置成本可能大于收益。业务收益需要真实试用统计漏任务率、误过滤率、引用支持率、草稿修改量和端到端耗时。

本轮验证了合成数据下的工程行为，没有增加真实账号权限、真实 SMTP 投递或主模型准确率的验证。之前的 Qdrant 本地检索小样本评估并未证明混合检索全面优于关键词，不能以使用向量数据库推断业务收益。

## 结构与可用性

前端从单个长组件拆为页面组件、工作台状态协调和独立 Trace/运行记录/日程组件，导航按邮件、工作、管理分组，原始 JSON 收入调试详情。后端继续复用 LangGraph、风险策略、账本、审计与计价，新增工作台查询聚合，移除旧版 SMTP 直发。

仍可改进：过滤配置主要是 JSON，非技术用户需要表单向导；待办完成当前仍需审批；提醒目前只有 Web 通知，没有系统推送；通用 records/JSON 的约束和前端部分 any 可逐步收紧；轮转调度不抢占长网络调用。旧历史记录保留，但无需把所有历史功能重新放回主导航。

## 最新验证

- 229 项后端测试通过（1 条第三方 AnyIO 弃用警告）。
- 120 条合成规则回归通过；这不代表真实 LLM 准确率。
- TypeScript、Vite 构建及 3 条 Playwright 流程通过。
- 浏览器覆盖邮件草稿审批/Trace、计价、日程审批/执行反馈、通知已读及小屏无横向溢出，保留截图、录像、Playwright Trace。
- 本轮没有重跑本地模型消融，也没有调用真实邮箱服务做收发验收。
