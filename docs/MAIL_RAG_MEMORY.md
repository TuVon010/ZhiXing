# 检索、记忆与自主工具决策

## 检索

data/models/manifest.json 保存不可变模型 revision 和 SHA256。E5 输入遵循 query:/passage: 前缀，CPU 归一化编码。320 Token 分块、48 Token 重叠；关键词降级使用明确标记的字符切块。

账号、日期、联系人和可见状态先过滤；FTS5 与 Qdrant local 各召回 40，RRF 常数 60 融合取 20，MiniLM 重排序选最多 8。块保留邮件、线程、附件页码或段落。SQLite 向量缓存键为内容哈希与模型版本，可在 Qdrant 索引损坏或升级后重建向量库。

已过滤的邮件即使仍有索引也被 SQL 排除。模型不可用、向量不完整均报告降级。更换模型建立独立候选数据库，资料未变化才切换账号索引；SQLite 与 Qdrant 是两个存储，切换不能构成跨库事务，Qdrant 写入失败时保留 SQLite 缓存供重建。Qdrant local 有进程文件锁，运行时仅由 Worker 访问；备份前停止服务，并同时保存 `data/qdrant` 与 SQLite 数据库。

SQLite 避免额外 Windows 服务与备份链。精确检索成本线性增长，大规模场景应测量后再迁移 ANN，不为技术数量引入更多服务。

## 四层记忆

1. 当前线程的来源证据。
2. 经确认、有限长度的长期偏好和事实。
3. 按需召回的历史交互/决策。
4. 邮件知识库和附件索引。

借鉴 Hermes 的有限记忆、冻结快照和按需召回思路，自主实现而非集成其运行时。SQLite 是主存储，USER.md/MEMORY.md 为每轮可读快照，各约 2,000 字符预算。账号偏好隔离，全局偏好须明确确认；新批准记忆从下一轮生效。第三方陈述只能形成候选，Agent 无权自行发布。撤销不改写旧运行历史快照。

## 工具循环

真实模型每轮选择 search/thread/attachment/history/tasks/draft/actions/memory/answer/clarify。服务端重新校验账号和工具权限，模型参数不能扩大作用域。最多 6 轮、3 次检索、24,000 输入 Token，前置保守估计并记录实际 usage。每轮决策与工具结果持久化。

模型不能直接发信，只能生成草稿。用户申请审批后由 LangGraph 与执行账本处理副作用。分类等调用复用预算和计价入口。

引用只能指向已读取且当前可见的证据；ID 校验不能替代语义支持评测。相似度不能证明事实，必须考虑更正与上下文。

## 评测解释

关键词/向量/融合/重排序分别测量，不预设越复杂越好。200 场景合成集按完整线程和项目分组。检索 Recall 不能推导答案正确率、记忆收益或任务完成率；未运行主模型的指标明确为空。
