# 知行工作台逐页学习地图

本目录对应左侧导航的 **15 个页面**。先看页面要解决的问题，再沿“前端组件 → API → Worker/业务函数 → 持久化记录 → 测试”阅读。这里描述的是当前代码行为；设计目标与未验证能力会明确区分。所有接口均以 `/api` 为前缀，需要先访问本机 `/api/session` 建立会话；修改请求还要带 `x-zhixing-local: 1`。普通用户通过工作台操作即可。

| 分组 | 页面文档 | 核心对象 |
| --- | --- | --- |
| 邮件 | [收件箱](01-inbox.md) · [回复草稿](02-drafts.md) · [过滤箱](03-filter-box.md) | `mail_message`、`mail_draft`、过滤状态 |
| 工作 | [待办与跟进](04-work-items.md) · [审批中心](05-approvals.md) · [运行记录](06-activity.md) · [通知与提醒](07-notifications.md) · [日程](08-calendar.md) | Todo、跟进、Approval、Run、Reminder |
| 工作 | [邮件 Agent](09-assistant.md) · [知识检索](10-search.md) | 会话、工具步骤、检索证据 |
| 管理 | [收取与导入](11-imports.md) · [邮箱账号](12-accounts.md) · [记忆](13-memory.md) · [设置与计价](14-settings-pricing.md) · [记录管理](15-records.md) | 账号、游标、批次、记忆、计价、回收站 |

推荐练习顺序：12 → 11 → 01 → 03 → 10 → 09 → 04/08 → 02/05 → 06/07 → 13/14/15。可以先在“邮箱账号”创建 14 封合成邮件的测试账号：测试邮箱无真实收发；真实模式下分析样本仍会调用你配置的模型。每轮回归资料见 [`artifacts/test-runs/`](../../artifacts/test-runs)，具体方法见 [测试研究指南](../MAIL_TESTING.md)。

贯穿全程的几个边界：本地分类、归档、回收站不修改远端邮箱；选中账号范围才允许 Agent 或检索读取；邮件和附件内容是证据而不是指令；发送前由用户审最终草稿，SMTP 接受不代表收件方已收到。模型不可用时检索页面会显示降级，不能把演示或模拟结果当作真实渠道验收。
