# 首页工作台

首页不是各模块数量的汇总，而是知行每天的行动入口。它按照“下一步行动、时间安排、Agent 产出、重要邮件”的顺序组织信息。

## 信息层级

- **今日简报**：当天新邮件、完成分析、过滤结果、逾期事项和未来七天日程。
- **下一步行动**：自动合并本地待办和邮件跟进，按照逾期、今天截止、需要回复、未来截止和等待他人排序。
- **日程时间轴**：突出下一场日程，展示当天时间轴，并可展开未来七天。
- **Agent 最近产出**：显示新邮件完成分类、摘要、待办、日程和回复意图识别后的结果。
- **重要邮件**：保留最近七天包含行动、日程或回复意图的邮件；仅未读不会进入这里。
- **快捷问答**：用户明确选择邮箱范围后，从邮件、线程和确认记忆中继续检索。

## 业务对象边界

| 对象 | 含义 | 首页操作 |
| --- | --- | --- |
| 日程 | 固定时间发生并占用时间段 | 进入日历查看或修改 |
| 待办 | 用户需要主动完成 | 完成、查看源邮件 |
| 邮件跟进 | 等待回复或等待外部结果 | 查看线程、标记解决 |
| 提醒 | 由待办或日程派生的通知机制 | 延后、完成或关闭 |

明确且低风险的本地事项由策略门自动保存；证据不足或时间冲突的内容进入“待核实建议”。发送邮件等外部副作用仍需审批。

## 实现链路

前端 HomePage.tsx 调用 GET /mail/home 获取首页读模型，复用工作区的 ask() 发起持久化 Agent 轮次。后端 mail_api.py 按邮箱作用域和 Asia/Shanghai 时间边界聚合邮件、任务、日程、跟进、提醒和队列状态。页面选择、邮箱范围和收件箱筛选保存在浏览器本地。

## 实时更新

启用邮箱后，Worker 默认每 15 秒执行一次 UID 增量扫描。新邮件依次进入过滤、存储、索引和 Agent 感知队列，完成后通过 SSE 刷新首页。首页邮箱状态显示最近检查时间和后台任务数，因此可以区分“尚未收取”“等待分析”和“已完成处理”。

首页是工作摘要，不代替收件箱和工作台的完整管理。统一收件箱不会自动授予 Agent 跨账号读取权限；发送邮件仍需审批，测试数据只有用户明确开启后才展示。
