# 知识检索

## 功能与使用

显式选择一个或多个邮箱，输入要查的事实、联系人或术语。页面返回带邮件/附件位置的证据块，可点击来源回收件箱，并展开排名与索引版本。这里主要负责**找证据**，不会自行给出经过推理的最终答复；需要问答时转“邮件 Agent”。跨邮箱检索必须由用户逐个勾选。

## 实现链路

[`AssistantPage.tsx`](../../frontend/src/mail/AssistantPage.tsx) 的检索模式调用 `POST /search`，创建后台搜索任务；[`mail_worker.py`](../../backend/mail_worker.py) 调 [`mail_rag.py`](../../backend/mail_rag.py)。索引阶段对邮件和已解析文本附件分块，保存来源、线程、位置、内容哈希与模型版本。查询先按账号、日期、联系人和本地可见状态过滤，再用 SQLite FTS5 的中文预分词词项与本地 E5 向量各召回，RRF 融合、MiniLM 重排序；向量索引使用嵌入式 Qdrant，SQLite 保留可重建缓存。被过滤、回收站或不在所选账号范围内的证据不可返回。

模型缺失或索引尚未完成时，返回 `degraded`、`mode`、`reason`，通常降级为关键词；这不是完整的混合 RAG。服务端返回 `evidence`、位置和耗时，便于核查是否真找到了支持答案的文本。可从“设置与计价”按账号重建索引。实现细节见 [RAG 设计](../MAIL_RAG_MEMORY.md)。

## 调试提示

用同一问题对比精确关键词与语义改写，检查相关邮件是否在前几条、引用是否能跳到正确来源。先看邮件的 `index_status`，再看检索 `mode/degraded/reason`，最后查索引 Worker 日志。不要仅凭相似度把邮件内容当作事实。
