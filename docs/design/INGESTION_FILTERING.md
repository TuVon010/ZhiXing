# 消息接入与过滤完善方案（尚未实施）

2026-09-22：本轮先完成自定义计价；以下按用户要求仅分析现状和设计，不修改收取行为。

## 当前现状与大量读取的原因范围

`backend/channels.py::poll_mail` 每轮 IMAP SEARCH ALL 获取 UID 索引；这不等于下载每封正文。首次没有游标时默认设为最大 UID 跳过旧邮件。已有游标则逐批下载 UID 更大的邮件正文，每轮写死最多 100 封，Worker 约每 30 秒继续下一轮。因此 100 是每轮上限，不是启动后总量上限；离线积压会持续补读。显式历史导入每次从尚未导入的旧邮件中选最多 100 封。

本地只读核对发现约 12 分钟内存入 1,007 封邮件（聚合统计，无正文/地址输出）。这证明存在大量入库，但不能据此断言用户触发了哪次历史导入；目前游标缺少变更原因和导入批次审计，无法完整还原起因。

代码风险：实时和历史导入共用 mail-cursor；历史导入推进这一游标，首次历史导入后轮询可能继续补读剩余邮件。API 历史导入与 Worker 未对同一邮箱互斥。没有日期范围、过滤、暂停、积压总预算和单独的收取/处理额度。邮件 timestamp 当前写的是入库时间，后续按历史邮件实际时间筛选须保留 INTERNALDATE、Date 头和 received_at，不能直接使用现有 timestamp。

飞书通过 SDK 长连接订阅 im.message.receive_v1，不是全账号聊天记录读取。代码限制：群必须在允许列表；私聊必须来自绑定用户；未绑定时进入绑定申请。代码没有历史分页拉取，也没有显式“仅 @机器人”判断。平台能推送哪些消息由应用权限决定：群 @ 消息和所在群全部消息是不同权限，普通机器人不能据此获取你与其他人的所有私聊。

## 建议交互和默认值（待下一轮实施）

1. 首次连接默认“从现在开始”；可显式选择最近 24 小时/7 天/自定义区间预览。显示预计匹配数量，再创建有总量上限的导入批次。
2. 断线恢复检测积压，显示待同步数量。建议最多自动补读最近 24 小时、每次恢复累计 50 条，其余暂停等待用户选择；不把每 30 秒的轮次当作新的恢复预算。
3. 分别配置每轮扫描数（如 20）、每分钟/小时处理数、单次历史导入总数（如 100）、模型调用预算。限制超出的消息保留待处理状态，不悄悄丢弃或推进已处理游标。
4. 设置页显示渠道启停、当前游标/时间、队列积压、最近收取/过滤/模型处理数量，提供暂停接入、暂停处理、取消某批次和清空某批次待处理队列的独立入口。取消不删除来源邮件、不撤销已完成外部操作。
5. 历史区间采取 [start, end)，界面明确时区。IMAP 日期过滤先粗筛，再按服务端 INTERNALDATE 精确判断；Date 头只作发送方声明时间，防止伪造/错误日期影响游标。

## 过滤流水线

连接器 → 持久化来源元信息 → 规则判定 → 待处理/过滤/待复核 → Agent 理解与计划。

- 先只取必要头部和大小，白名单联系人/域名、黑名单、主题关键词、收件文件夹、List-Unsubscribe/List-Id、群发特征组合判定。单一“带退订链接”不能直接判废，重要通知也会带它。
- 将“广告营销”“订阅资讯”“事务通知”“待办/承诺”“需人工确认”分类。白名单优先，低置信度进入待复核；无需每封广告都请求大模型。
- 规则不确定时可用有额度的分类模型或 Jev 影子评分，但先建立中文标注集，验证误杀率和成本；不能假设 Jev 已能可靠识别所有广告。
- 被过滤消息进入本地过滤箱，记录规则版本、命中证据、原因、人工纠正，不删除远端邮件、不自动退订、不按营销正文链接执行操作。
- 允许“恢复并处理这封”和“以后此发件人放行”；修改规则能对本地元信息预览影响，不重复触发已确认外部操作。
- 飞书按群独立配置“仅 @机器人 / 仅本人发言 / 指定发送人 / 允许全部”；先检查平台权限，不声称本地开关能扩大远端权限。

## 持久化和可靠性

实时 cursor、历史 import_job 的分页游标分离；同邮箱持久化租约互斥，使用 UIDVALIDITY＋UID 稳定去重。来源入库与队列入库必须可恢复；过滤也要留记录，不能下一轮又读回。重启保留批次范围、累计额度和暂停状态。UIDVALIDITY 改变时要求明确恢复策略，不偷偷全量重扫。

邮件正文按需要下载，设置单封大小上限和超限状态；来源时间、抓取时间、过滤耗时、处理耗时、丢弃/保留原因分开记录。历史导入预览不触发 Agent，不产生发送或任务副作用。

## 验收计划

模拟有 5,000 封旧邮件的首次接入，验证默认不导入旧正文；模拟离线积压、跨轮额度、日期边界、广告误判/恢复、并发历史导入、UIDVALIDITY 改变及崩溃恢复。飞书覆盖未允许群、非本人私聊、@ 模式与批次限制。保存每条样本、过滤标签/理由/版本、入库与处理计数、模型成本、误杀率/漏拦率。真实邮箱/飞书联调另记，不把模拟当真实验证。

实施顺序建议：先补暂停与限量、拆分游标和历史批次；再加时间范围和预览；再做过滤箱和规则；最后评测模型辅助分类。
