# 邮件检索评测 V2：样本扩充与可复现实验

本方案评估的是“用户能否找到并引用正确的邮件证据”，而不是让某项技术必然取得正向结果。先锁定样本、标签、指标和判定阈值，再运行各检索模式；失败和退化同样留档。主模型生成答案、分层记忆的效果需要另做端到端实验，不能由检索指标推断。

## 已有结果应该怎样理解

2026-09-23 的 [旧报告](RAG_EVALUATION_REPORT.md)只有 17 封合成邮件、20 条查询，其中“语义类 Recall 0.667→1.000”来自 **3 条语义查询**，标签还是发件人而不是具体邮件/证据。3/3 只能说明这 3 条都命中，不能说明普遍语义查询有 100% 召回；旧报告的“Recall@1”也不是标准的排名第一位召回率。旧报告运行于 Qdrant 接入之前，不应与当前实现直接混算。

仓库另有 [200 条合成查询的运行脚本](../scripts/evaluate_mail.py)，使用真实本地 E5、Qdrant local 和 CrossEncoder；它的 200 条由 **10 种问题模板 × 20 个项目编号**构成，优化集与保留集共享模板，因此不能视为 200 个独立问题。对 `artifacts/mail-evaluations/20260923-085719` 重新按相关邮件 ID 和固定 K 计算，保留集（100 条）的结果如下。完整逐例结果保存在 `artifacts/mail-evaluations/audit-20260928-194042`；这个目录是本地研究资料，默认不提交公开仓库。

| 模式 | Precision@1 | Recall@5 | Recall@8 | nDCG@8 | 平均耗时 | P95 耗时 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| FTS5 关键词 | 0.64 | 0.70 | 0.74 | 0.516 | 6.9 ms | 16 ms |
| E5 + Qdrant 向量 | 0.96 | 0.855 | 0.95 | 0.935 | 42.47 ms | 47 ms |
| 双路 RRF 融合 | 0.82 | 0.99 | 1.00 | 0.813 | 42.05 ms | 47 ms |
| 融合 + CrossEncoder + 证据筛选 | 1.00 | 0.75 | 0.75 | 0.904 | 632.48 ms | 719 ms |

这些数字证明**在这份模板化数据上**，向量和融合提高了召回；但最终链路丢失了部分相关邮件。`Precision@1=1.00` 也不能抵消 `Recall@8=0.75`，因为一次查询可能需要两封邮件才能解释截止时间的更正。所有查询都要求回答“最新截止时间”，特别容易让重排器偏向更正邮件并丢掉原邮件。必须在新测试中区分“最终回答只需更正邮件”与“必须展示变更链”两类标签，不能事后改标签迎合结果。

2026-09-28 的完整运行归档为 `artifacts/mail-evaluations/vector-baseline-20260928-195902`。各模式使用同一批邮件、账号范围和相关邮件标签：

| 模式 | 全部 Recall@8 | 全部 Precision@1 | 语义类 Recall@8 | 更正类 Precision@1 | 平均耗时 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 关键词 | 0.867 | 0.533 | 0.600 | 0.133 | 2 ms |
| 向量 | 1.000 | 0.711 | 1.000 | 0.200 | 42 ms |
| RRF 融合 | 1.000 | 0.667 | 1.000 | 0.267 | 42 ms |
| 融合＋重排 | 1.000 | 0.644 | 1.000 | 0.067 | 431 ms |

这轮试验支持**把默认检索先切为向量**：它在这批问题上的召回、首位命中和耗时均优于原默认的融合重排；关键词保留为降级回退。但每个账号只有约 15 个主题，语料较小，且标签由样本编写者给出；`Recall@8=1.000` 很可能受到小语料和简单问题影响，不能写成真实业务的 100% 召回。更正类 Precision@1 只有 0.200，说明“最新版本判断”仍需要线程展开与时间冲突判断；不能仅凭 Top-1 检索结果回答。正式提升幅度必须等待下面的独立标注保留集。

目标建立至少 **150 条独立撰写的可回答问题**，另设至少 **20 条无答案问题**；语料至少 **300 个不同邮件线程 / 500 封邮件**，覆盖至少 3 个模拟账号。样本以完整线程为单位切分：可回答问题的开发集约 50 条，锁定保留集约 100 条；同一邮件、线程、事件、项目、问句模板及近义改写不得跨集。每条可回答问题至少有一个真实可定位的邮件证据；无答案问题不能混入 Recall 的分母。可先用合成/脱敏邮件，真实邮件只有用户明确同意且脱敏后才能用于私有评测。

各类问题分别给出数量和结果，不只报告总体平均：精确人名/编号/术语，语义改写，截止时间更正，跨邮件组合，附件段落，否定与冲突信息，过期版本，多账号隔离，广告噪声，以及无答案。语义改写需要人为撰写不同说法，不能只是替换项目编号。至少设置相似主题、相同发件人但不同任务、同任务不同版本这三类硬负例，防止关键词或向量靠表面相似度得高分。

建议标注文件为 UTF-8 JSONL，每行至少包含：

```json
{"query_id":"q001","split":"holdout","category":"temporal_correction","account_ids":["account-a"],"question":"周会的最新时间？","answerable":true,"relevant":[{"message_id":"mail-123","chunk_id":"chunk-7","grade":2,"evidence_span":"改为周五下午三点"}],"expected_answer":"周五下午三点","must_show_change_chain":false,"annotation_status":"adjudicated"}
```

`grade=2` 表示足以支持答案，`grade=1` 表示有用背景，`grade=0` 为不相关；多封邮件共同必要时分别标注，并说明是否必须展示变更链。标注员先只看邮件和问题，不看系统检索排名；两人独立标注，分歧复核。记录标签版本、标注人、分歧和最终裁决。邮件引用应落实到 `message_id + chunk_id + 文本片段`，不以发件人或主题代替证据。对无答案问题记录预期拒答/澄清，而不是虚构相关邮件。

## 统一实验设置

1. 冻结语料、问题、标签、开发/保留切分、账号权限、模型权重及哈希、分词/索引版本、Qdrant 集合和代码提交号。所有模型、临时文件与缓存按项目环境脚本放在 E 盘。
2. 完整索引后，先验证每封邮件和附件段落的索引状态；降级或索引失败要单列，不能悄悄计入完整 RAG。固定相同的账号、日期、可见性过滤。查询顺序固定随机种子；先预热再计时；单线程和有限并发分别测，记录 CPU、内存及首次加载耗时。
3. 对同一问题依次运行 `keyword`、`vector`、`fusion`、`hybrid`，四种模式取相同最多 8 个最终证据；保存**候选 Top40、RRF Top20、重排 Top20、最终 Top8** 及每层被丢弃的相关证据。现有旧归档只保存最终证据，不能事后定位全部丢失环节，因此 V2 运行器需要扩展这部分记录。
4. 对 RRF 的权重、重排数量、来源多样性阈值只在开发集调整。规则确定后一次性运行保留集，不看结果反复调参。若修改代码或标签，开新版本、新归档，并保留失败轮次。
5. 若比较记忆和问答，另外固定主模型、Prompt、温度、Token 预算和相同检索证据，单独跑“无记忆/有确认记忆”“固定检索/自主检索”消融。标记模型服务、Token、成本、缓存命中及引用支持率；没有主模型调用时这些字段写“未测”，不能填 0。

每次运行保留：`dataset.jsonl`、脱敏语料版本/校验和、标注裁决、`manifest.json`、模型哈希、命令与环境、逐例四模式排名、分层候选、耗时、失败与降级记录、统计脚本和汇总报告。所有测试数据库与原始 Trace 保存在 `artifacts/` 下，每轮独立目录；不覆盖已有历史归档。公开提交只包含合成/脱敏样本和可复现脚本，不包含私人邮件、凭证与个人研究资料。

## 指标与预先判定

以**邮件和证据块**分别统计 Precision@1/3/5/8、Recall@1/3/5/8、nDCG@5/8、MRR@8；主指标建议选保留集的 `nDCG@5` 和语义类 `Recall@5`。同时统计“回答的每条关键结论有证据支持”的比例、无答案拒答率、账号越权率、P50/P95 延迟和内存。多证据问题还要有“必需证据全部找齐率”；否则只命中更正邮件也可能被误判为完整回答。固定 K 的 Precision 分母必须是 K；`Recall@1` 是排名第一封邮件的相关命中数除以该问题的相关邮件数。

每条问题做配对比较，按**事件/线程或问题家族**聚类自助采样，给出差值及 95% 区间，避免把同模板变体误当独立观测。重点报告：向量−关键词、RRF−关键词、最终链路−RRF；全部类别和失败例都要列出。保留集通过条件应在开测前确定，例如：语义类 Recall@5 明确高于关键词、总体 nDCG@5 不低于关键词超过 0.02、关键任务证据找齐率不下降、P95 延迟满足产品目标，以及账号越权为 0。若区间跨 0，只能写“未证实提升”。样本不足或标签分歧未解决时暂停结论。

当前证据更适合表述为：**“在模板化合成评测中，向量检索提升了相关邮件召回；同时发现最终重排/筛选导致多证据召回退化，正在用独立标注集定位并修正。”** 在 V2 保留集验证之前，不建议宣称“混合 RAG 整体效果提升”或把 3/3 写成普遍 100% 召回。
